# Data Model: Registrar una cuenta

## User (`accounts.users`)

Owned by the `accounts` module.

| Field | Type | Rules |
| --- | --- | --- |
| `id` | `BIGINT` | Primary key, generated by the database. |
| `full_name` | `VARCHAR(100)` | Required by HU-01; 2–100 Unicode letters/marks, spaces, apostrophes or hyphens after trimming. Nullable in storage only for users created by the earlier login migration. |
| `phone` | `VARCHAR(10)` | Required; exactly 10 ASCII digits beginning with `3`; unique. |
| `national_id` | `VARCHAR(20)` | Required by HU-01; 5–20 ASCII alphanumeric characters, stored uppercase and immutable. Nullable in storage only for pre-HU-01 users. |
| `email` | `VARCHAR(254)` | Required by HU-01; valid email structure, trimmed, stored lowercase and unique. Nullable in storage only for pre-HU-01 users. |
| `password_hash` | `VARCHAR(255)` | Required Argon2id encoded hash; never exposed. |
| `created_at` | `DATETIME(6)` | Required, server-generated UTC timestamp. |
| `updated_at` | `DATETIME(6)` | Required, server-generated and updated UTC timestamp. |

### Constraints and indexes

- Primary key: `pk_users (id)`.
- Unique: `uq_users_phone (phone)`.
- Unique: `uq_users_email (email)`.
- Unique: `uq_users_national_id (national_id)`.
- The service canonicalizes values before insertion; constraints remain the authority
  for concurrent requests.
- `0002_users_wallets` extends the `users` table created by the login migration
  `0001_create_users_and_sessions`; it does not create a second `users` table.

### Invariants

- No plaintext password is present in the entity or persistence mapping.
- The identification number does not have an update path.
- An account is valid only when exactly one wallet exists; the registration transaction
  establishes the relationship atomically.

## Wallet (`wallet.wallets`)

Owned by the `wallet` module.

| Field | Type | Rules |
| --- | --- | --- |
| `id` | `BIGINT` | Primary key, generated by the database. |
| `user_id` | `BIGINT` | Required foreign key to `users.id`; unique. |
| `balance` | `DECIMAL(15,2)` | Required; default `0.00`; check `balance >= 0`. |
| `created_at` | `DATETIME(6)` | Required, server-generated UTC timestamp. |
| `updated_at` | `DATETIME(6)` | Required, server-generated and updated UTC timestamp. |

### Constraints and indexes

- Primary key: `pk_wallets (id)`.
- Unique one-to-one relationship: `uq_wallets_user_id (user_id)`.
- Foreign key: `fk_wallets_user_id_users`, with deletion restricted.
- Check: `ck_wallets_balance_nonnegative (balance >= 0)`.

### Invariants

- Initial balance is exactly `Decimal("0.00")` / `DECIMAL(15,2)`, never a floating-point
  value.
- A wallet cannot exist without its user and a user cannot receive a second wallet.
- HU-01 never creates a movement for the initial zero balance.

## Relationship

```text
User 1 ───── 1 Wallet
```

The ORM relationship is navigable inside the owning implementation as needed, but
cross-module behavior uses services rather than importing the other module's model.

## Registration transaction

1. Validate all request fields before opening persistence work.
2. Canonicalize phone, identification and email.
3. Hash the password with Argon2id; discard the plaintext after use.
4. Begin one SQLAlchemy transaction.
5. Insert `User` through `accounts.repository` and flush to obtain `user.id`.
6. Call `wallet.service.create_wallet_for_account(user.id)`; it inserts `Wallet` through
   `wallet.repository` without committing.
7. Commit once. Any exception rolls back both rows.
8. Translate uniqueness violations to `duplicate_identity` without exposing the
   constraint name or submitted value.

## State transitions

Registration has no persistent intermediate state:

```text
nonexistent ──successful transaction──> active account + zero-balance wallet
nonexistent ──validation/conflict/error──> nonexistent
```

No session, verification state, movement or financial instrument is created.
